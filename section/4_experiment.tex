\subsubsection*{システムアーキテクチャ（層構造）}
以下の層構造により、研究用のオフライン分析と対話的な評価を同一コードベースで実現している。
\begin{enumerate}
	\item \textbf{データ層}: JSON/Markdown 形式のワーカーデータ、求人データを保持。
	\item \textbf{前処理層}: セッション検証、テキスト正規化、特徴抽出を行う。
	\item \textbf{モデル層}: Sentence-BERT による埋め込み生成と類似度計算。
	\item \textbf{推薦ロジック層}: 重み付けパターン、履歴平均ベクトル、ベースライン手法の切替。
	\item \textbf{評価層}: Top-K等の指標算出と学習曲線評価。
	\item \textbf{インタフェース層}: CLI 実行スクリプトと FastAPI Web GUI。
\end{enumerate}
また、本システムは、\textbf{Web GUI/CLI} を入口として \textbf{評価パイプライン} を起動する構成である。GUI層は FastAPI が担当し、ワーカー選択・実験条件（重み付けや特徴量モード）・進捗表示を提供する。GUI/CLI からの実行指示は評価層に渡され、\textbf{データ読み込み}（JSON/外部データ）→\textbf{前処理}→\textbf{特徴生成}→\textbf{推薦}→\textbf{評価}→\textbf{出力保存} の順に処理される。推薦層は「BERTベース」「ベースライン」を切り替え可能で、同一インタフェース上で比較できる。出力層は JSON/テキスト/HTML に対応し、再現性の高い記録を残す。

\subsection{評価パイプライン}
\subsubsection*{データフロー（処理パイプライン）}
\begin{enumerate}
	\item データ読み込み：ワーカー履歴と求人リストを取得。
	\item セッション検証：欠損や不正データを除外し、学習用・評価用に分割。
	\item 特徴生成：求人テキスト（タイトル・業務内容・介護項目など）を統合しベクトル化。
	\item スコアリング：平均ベクトルとのコサイン類似度、または特徴量スコアを計算。
	\item 推薦生成：Top-K を抽出し、正解求人の順位を評価。
	\item 出力保存：JSON/テキスト/HTML に結果と詳細ログを保存。
\end{enumerate}

\subsubsection*{データモデル（主要フィールド）}
実データはワーカー単位の履歴として保存され、セッションは「応募/勤務1回」を基本単位とする。評価では、各セッションに含まれる\textbf{ワーカーが選択した求人群}と\textbf{その時に提示されていた候補求人群}を用いる。
\begin{itemize}
\item \textbf{ワーカー情報}: ワーカーID（\texttt{workerId}）、氏名（\texttt{name}）、資格（\texttt{qualifications}）など。
\item \textbf{セッション情報}: 勤務日（\texttt{workDate}）、開始時刻（\texttt{startTime}）、職種名（\texttt{jobTitle}）、業務内容（\texttt{jobContent}）。
\item \textbf{求人情報}: 介護項目（\texttt{careItems}）、施設名（\texttt{facilityName}）、給与（\texttt{salary}）、交通費（\texttt{transportationAllowance}）など。
\item \textbf{求人候補集合}: その時点で提示された求人候補群（\texttt{availableJobs}）。
\end{itemize}

\subsubsection*{推薦アルゴリズム構成}
	\begin{itemize}
		\item \textbf{Sentence-BERT ベース}: 求人タイトル・業務内容・介護項目・施設・勤務条件など複数項目の重み付けで統合類似度を算出。
		\item \textbf{項目別の重み付け比較}: 求人を構成する複数項目（職種名、業務内容、介護項目、施設、勤務条件など）の重み配分パターンを比較し、最適構成を探索。
		\item \textbf{時間重み付け比較}: 履歴の新しさ（直近重視・長期安定など）を反映する時間重みパターンを比較し、嗜好のドリフトに頑健な設定を探索。
		\item \textbf{ベースライン}: 職種のみ／介護項目のみで推薦する軽量モデルを実装し、BERTとの差分を測定。
		\item \textbf{業務回避パターン}: 過去履歴から避けている業務を推定し、ペナルティを付与。ユーザースタディで得られた知見であるため、追加実験の章で詳述。
	\end{itemize}

\subsubsection*{スコア統合の考え方}
BERTスコアは職種や業務内容の\textbf{意味的距離}を評価し、条件差分や履歴平均との統合により総合スコアを構成する。利用頻度に応じて重みを動的に調整し、ライトユーザーとヘビーユーザーで推薦方針を切り替える設計としている。

\subsubsection*{評価設計}
	\begin{itemize}
		\item \textbf{Top-K精度}: Top-1/3/5 を基本指標とし、実務的推薦の再現性を評価。
		\item \textbf{複合スコア}: アプリでは最終的に\textbf{おすすめを1件}提示する想定であるため、Top-1を重視した総合評価として、Top-1/3/5（それぞれ$T1, T3, T5$）を次式で1つの値に集約する（各Top-K精度は0〜1）。
	\[
	S_{\text{composite}} = 0.5\,\text{Top-1} + 0.3\,\text{Top-3} + 0.2\,\text{Top-5}
	\]
		と定義する（例：Top-1=39.0\%は0.390として扱う）。
		\item \textbf{分割方法}: 段階的学習評価では、履歴の最初の\textbf{10件を固定テストデータ}として、その後に続く履歴データを学習データとして$k$件用意し、精度を算出する（$k$を変化させて学習曲線を得る）。
		\item \textbf{学習曲線評価}: 学習件数を段階的に増やして性能変化を分析。
	\end{itemize}

\section{予備実験1：日本語BERTモデルによる単語間類似度測定}
自然言語処理モデルの代表例としてBERTがある。本研究では日本語に特化したcl-tohokuモデルを利用し、単語間のコサイン類似度を計測した。しかし、「介護」と「極悪非道」の類似度が0.678であったり、「看護師」と「ナース」よりも「介護士」と「ナース」のほうが数値的に近かったりと、直感とずれる結果が得られた。この結果から、単一モデルに依存せず、横断的に複数モデルを検討する重要性が示された。
\section{予備実験2：BERTモデルの横断評価}
予備実験1の結果を受け、単語レベルではなく\textbf{職種表現全体の意味}を捉えやすい埋め込み表現を前提に、複数のBERT系モデルを横断的に比較した。評価指標として、アンカー職種に対して「類似職種の平均スコア」と「非類似職種の平均スコア」の差を取り、\textbf{分離度}として定義する。分離度が大きいほど、類似/非類似をより明確に区別できる。

	\subsubsection*{CLS・平均プーリング・Sentence系の違い}
	BERT系モデルは入力文をトークン列として処理し、各トークンに対応する埋め込みを出力するため、「文全体」を1本のベクトルにまとめる\textbf{プーリング}が必要になる。
	\begin{itemize}
		\item \textbf{CLS埋め込み}: 文頭に付与される\texttt{[CLS]}トークンの最終層ベクトルを文表現として用いる。分類タスク向けに設計された表現であり、短文や語順の揺れに対して文意が不安定になる場合がある。
		\item \textbf{平均プーリング（mean pooling）}: 最終層のトークン埋め込み（\texttt{[PAD]}を除く）を平均し、文表現とする。文中の情報を広く集約できるため、短文の意味が安定しやすい。
		\item \textbf{Sentence-BERT（Sentence系）}: Sentence-BERTのように\textbf{文同士の類似度}が直接高くなるよう学習（対照学習・ペア学習など）されたモデルであり、コサイン類似度での近さが「文意の近さ」に対応しやすい。
	\end{itemize}
	本研究では、これらの表現方式の違いが分離度に与える影響を確認した。

\section{本実験1：均等重みによる統合推薦}
本実験1では、求人タイトル、業務内容、介護項目、施設、勤務時間、時給、勤務日といった複数項目を統合し、\textbf{すべてを同一比率（均等重み）}で推薦スコアを構成した。現実の応募判断は「仕事内容が合うか」「条件が合うか」「施設が合うか」など複数の観点が同時に影響するため、まずはそれらを一つの枠組みにまとめたときの基準性能を確認する。
本実験1は、項目ごとの重要度をまだ調整しない段階に位置づけられるため、以降の比較実験における出発点（基準条件）として機能する。

評価には18名分の実データを用いた。過去履歴のうち先頭から一定数を学習として用い、その直後の10件をテストとして逐次評価することで、学習件数を段階的に増やした場合の推移を測定した。
精度指標としては、各テストで実際に選ばれた求人が推薦リストの\textbf{上位1件/上位3件/上位5件}に含まれるかを判定し、その一致率をワーカーごとに集計したうえで平均した。

表\ref{tab:exp2-learning-curve-equal-20workers}より、学習件数が増えるほど単調に改善するわけではなく、一定以上の履歴を取り込むと精度が低下する傾向が見られる。
また、アプリでは最終的におすすめを1件提示する想定であるため、Top-1を重視した総合評価として複合スコア（$0.5\times$Top-1 $+ 0.3\times$Top-3 $+ 0.2\times$Top-5）も併記している。
複合スコアは「上位に1件だけ出せればよい」という運用要件を反映しつつ、単発の一致・不一致に左右されやすいTop-1だけに依存しないよう、上位3件・上位5件での一致も補助的に加味するための指標である。したがって、同じTop-1であってもTop-3/5が高い条件は、実運用での候補提示の安定性が高いと解釈できる。
この結果は、履歴を長く取るほど情報量が増える一方で、\textbf{過去の応募が必ずしも現在の関心を代表しない}可能性を示している。たとえば、働ける曜日や時間帯の変化、施設との相性、業務の得手不得手などにより、重視点が時間とともに移り変わる場合がある。
そこで次の本実験2では、項目別の重み付けを変えることで、均等重みからどの程度改善できるかを検証する。

\section{本実験2：複数項目の重み付けによる精度向上}
本実験1では、複数項目を統合したとしても\textbf{均等重み}だけでは精度が頭打ちになり、学習件数を増やすと精度が低下する傾向も観察された。推薦においては、同じ求人でも「仕事内容が近いこと」を重視する人と「勤務条件が合うこと」を重視する人が存在し、\textbf{どの観点を強く反映すべきかはワーカーごとに異なる}と考えられる。
本実験2ではこの点に着目し、\textbf{項目別の重み付け}を系統的に変化させることで、推薦精度にどの程度の差が生じるかを評価する。

具体的には、求人タイトル、業務内容、介護項目、施設、勤務時間、時給、勤務日など7項目について、相対的に強調する項目を変えた複数の配分を用意し、同一の評価手順で比較した。評価指標は、上位1件・上位3件・上位5件の一致率に加え、アプリでおすすめを1件提示する運用を踏まえ、上位1件を重視した\textbf{複合スコア}（$0.5\times$Top-1 $+ 0.3\times$Top-3 $+ 0.2\times$Top-5）も用いる。
ここでの目的は二つある。第一に、\textbf{項目重みの違いが精度差として現れるか}を確認し、重み付け設計が推薦性能に与える寄与を定量的に示すことである。第二に、本実験1で見られた「履歴を増やすと精度が落ちる」傾向が、重み付けを変えることでどの程度緩和されるかを確認することである。

\section{本実験3：時間重み付け比較}
本実験1・2では、重み付けにより精度差は生じるものの、学習件数が増えると精度が低下する傾向が共通して観察された。これは、古い履歴が現在の嗜好から外れていく影響が無視できないことを示唆する。そこで本実験3では、\textbf{履歴の新しさを評価に反映する}時間重み付けを導入し、この傾向を緩和できるかを検証する。

具体的には、過去履歴の寄与に対して、直近ほど大きな重みを与える減衰関数（指数・線形・ウィンドウ・セッション順など）を比較する。本実験3では本文の議論を明確にするため、特徴量配分を\textbf{均等（\texttt{equal}）}に固定し、時間重み付けの効果に焦点を当てる。他の特徴量配分を含む詳細な結果は付録\ref{app:exp3-time-weighting-details}にまとめた。以降の結果は、\textbf{学習ステップ20（履歴20件）}を主に用い、学習ステップ別の推移は表\ref{tab:time-weighting-steps}に示す。

主要な時間重み付けの代表例は付録\ref{app:weight-patterns}に移し、本文では考え方のみを簡単に整理する。
\begin{itemize}
	\item \textbf{時間減衰なし：}全履歴を同一の重みで参照する基準。
	\item \textbf{指数減衰：}履歴が新しいほど重く、古いほど急速に軽くする。最近の応募・閲覧に強く引っ張られるため、嗜好が短期間で変わるユーザーに対して追従しやすい。一方で、過去の安定した好みを反映しにくくなる場合がある。
	\item \textbf{線形減衰：}履歴の新しさに応じて重みを一定の割合で段階的に小さくする。指数減衰よりも「古い履歴もある程度は残す」形になりやすく、短期と長期のバランスを取りたい場合に適する。
	\item \textbf{期間制限型：}一定期間内の履歴だけを参照し、それ以前は参照しない。古い履歴の混入を確実に防げるため、嗜好の変化や季節要因の影響を受けやすい場合に有効である。
	\item \textbf{セッション順の減衰：}日付ではなく行動の順序で「新しさ」を定義し、直近ほど重くする。タイムスタンプの精度が十分でない場合でも、相対的な新旧を用いて最近の行動を優先できる。
\end{itemize}

18名データでは、特徴量配分を\texttt{equal}に固定した場合でも、\textbf{直近重視の指数減衰}が複合スコア=0.6339（Top-1=0.5556, Top-3=0.6944, Top-5=0.7389）で最良となった。\textbf{直近30日線形減衰}は複合スコア=0.6139（Top-1=0.5333, Top-3=0.6722, Top-5=0.7278）、\textbf{時間減衰なし}は複合スコア=0.5661（Top-1=0.4778, Top-3=0.6278, Top-5=0.6944）であり、最良パターンは時間減衰なしに比べて+0.0678の改善となる。短期の履歴を強く反映する設計が、集団平均では安定して有利であることが確認できる。なお、表\ref{tab:time-weighting-steps}は複合スコアのステップ別推移（有効ワーカー平均）である。

\section{本実験4：時間重み自動選択の実装と結果}
本実験3では、全体平均で見ると「最近の行動を重く見る」ほうが良い傾向があった。一方で、ワーカーごとに行動の変わり方は異なる。たとえば、いつも似た求人に応募する人もいれば、最近になって希望がガラッと変わる人もいる。

そこで本実験4では、\textbf{その人の履歴の様子を見て、時間重み付けを自動で選ぶ}仕組み（時間重み自動判別）を実装し、固定の方式（時間減衰なし・直近30日線形減衰）と比較する。

\subsubsection*{考え方（高校生向けに要約）}
ポイントは次の2つである。
\begin{itemize}
	\item \textbf{最近の行動が昔と同じ}なら、昔の履歴も参考にしてよい（長期安定）。
	\item \textbf{最近の行動が昔と違う}なら、最近を強く重くするほうがよい（短期追従）。
\end{itemize}
本研究の履歴には日付があるため、「最近を重くする」方式として\textbf{直近重視の指数減衰}（例：直近7日指数減衰）を、「長期を安定して見る」方式として\textbf{期間制限型}（例：直近90日ウィンドウ）を用意し、ワーカーごとに切り替える。

\subsubsection*{どうやって「変化したか」を測るか（ドリフト）}
自動選択で最も大事なのは「最近と昔がどれくらい違うか」を数で表すことである。本研究ではこの「違い」を \textbf{drift（ドリフト）} と呼ぶ。

やり方は次の通りである。
\begin{enumerate}
	\item 各履歴（求人の文章）を、Sentence-BERTで\textbf{数値のまとまり（ベクトル）}に変換する。
	\item 履歴を「最近の数件」と「それより前」に分ける（最近側は最小2件・最大5件、履歴長の1/3を上限）。
	\item それぞれの平均ベクトルを作る（最近：$\bm{v}_{\mathrm{recent}}$、昔：$\bm{v}_{\mathrm{past}}$）。
	\item 2つの「似ている度合い」をコサイン類似度 $s=\cos(\bm{v}_{\mathrm{recent}},\bm{v}_{\mathrm{past}})$ で計算する（$s$ が大きいほど似ている）。
\end{enumerate}
そして
\[
\mathrm{drift} = 1 - s
\]
と定義する。直感的には、\textbf{drift が大きいほど「最近と昔が違う」}ことを意味する（「似ている度合い」から「違い」を作っている）。

\subsubsection*{切替ルール（シンプル版）}
\begin{itemize}
	\item drift が小さい（ここでは 0.12 未満）：\textbf{あまり変化していない}とみなし、\textbf{期間制限型}（例：直近90日ウィンドウ）を使う。
	\item drift が大きい（0.12 以上）：\textbf{最近変化している}とみなし、\textbf{直近重視の指数減衰}（例：直近7日指数減衰）を使う。
\end{itemize}
このように、状況に応じて「長期を安定して見る」か「短期に強く追従する」かを切り替える。

実装上は、判定結果（採用方式、drift 値、直近ウィンドウ長）をワーカー単位にキャッシュし、同一履歴長での再計算を省略することで、繰り返し評価における計算コストを抑えた。

\subsubsection*{評価設定と結果}
検証は18名データ（読み込み成功18名）で実施し、特徴量配分は\textbf{均等（\texttt{equal}）}に固定した。学習ステップ20（履歴20件）を用い、時間重みだけを変えて平均Top-Kを比較した結果を表\ref{tab:time-auto-results}に示す。

\subsubsection*{18名データにおける時間志向の分布}
時間重み自動判別の判定結果から、18名データの時間志向を集計した。読み込み成功18名のうち、\textbf{短期志向が3名（16.7\%）、長期志向が15名（83.3\%）}であり、長期志向のワーカーが多数を占めた。これは、対象期間において大半のワーカーの履歴が「直近と過去で大きく乖離していない」ことを意味する。一方で短期志向に分類されたワーカーは drift が相対的に大きく、直近行動の重視が有効になりやすい。実運用では、季節要因や生活状況の変化（勤務可能時間の変化、施設との相性、希望職種の変化など）により志向が急変するケースも考えられるため、\textbf{短期志向の検出}は個別最適化において重要な役割を担う。

\subsubsection*{時間パターン別の優位性（18名データ）}
時間パターンの優位性をより俯瞰するため、全重み付けパターン（6種）における各時間パターンの平均Top-Kを集計した。その結果、\textbf{直近7日指数減衰}や\textbf{Softmax 7日}、\textbf{セッション線形減衰}が上位に並び、短期の情報を重視する設計が安定して高い精度を示した（表\ref{tab:time-pattern-ranking-20}）。これは本実験3の結論（古い履歴の混入が精度低下に繋がる）と整合的である。ただし、上位方式間の差は僅差であり、ワーカーごとの最適が分散する可能性も高い。このため、自動選択は「短期方式を常に採用する」ことではなく、\textbf{必要なときに短期へ寄せる}ためのスイッチとして設計することが望ましい。
