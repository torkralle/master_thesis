\begin{itemize}

	\item \textbf{データ/結果/テスト}: 実データ、出力、テストを分離配置。
\end{itemize}

\subsubsection*{システムアーキテクチャ（層構造）}
以下の層構造により、研究用のオフライン分析と対話的な評価を同一コードベースで実現している。
\begin{enumerate}
	\item \textbf{データ層}: JSON/Markdown 形式のワーカーデータ、求人データを保持。
	\item \textbf{前処理層}: セッション検証、テキスト正規化、特徴抽出を行う。
	\item \textbf{モデル層}: Sentence-BERT による埋め込み生成と類似度計算。
	\item \textbf{推薦ロジック層}: 重み付けパターン、履歴平均ベクトル、ベースライン手法の切替。
	\item \textbf{評価層}: Top-K等の指標算出と学習曲線評価。
	\item \textbf{インタフェース層}: CLI 実行スクリプトと FastAPI Web GUI。
\end{enumerate}
また、本システムは、\textbf{Web GUI/CLI} を入口として \textbf{評価パイプライン} を起動する構成である。GUI層は FastAPI が担当し、ワーカー選択・実験条件（重み付けや特徴量モード）・進捗表示を提供する。GUI/CLI からの実行指示は評価層に渡され、\textbf{データ読み込み}（JSON/外部データ）→\textbf{前処理}→\textbf{特徴生成}→\textbf{推薦}→\textbf{評価}→\textbf{出力保存} の順に処理される。推薦層は「BERTベース」「ベースライン」を切り替え可能で、同一インタフェース上で比較できる。出力層は JSON/テキスト/HTML に対応し、再現性の高い記録を残す。

\subsection{評価パイプライン}
\subsubsection*{データフロー（処理パイプライン）}
\begin{enumerate}
	\item データ読み込み：ワーカー履歴と求人リストを取得。
	\item セッション検証：欠損や不正データを除外し、学習用・評価用に分割。
	\item 特徴生成：求人テキスト（タイトル・業務内容・介護項目など）を統合しベクトル化。
	\item スコアリング：平均ベクトルとのコサイン類似度、または特徴量スコアを計算。
	\item 推薦生成：Top-K を抽出し、正解求人の順位を評価。
	\item 出力保存：JSON/テキスト/HTML に結果と詳細ログを保存。
\end{enumerate}

\subsubsection*{データモデル（主要フィールド）}
実データはワーカー単位の履歴として保存され、セッションは「応募/勤務1回」を基本単位とする。評価では、各セッションに含まれる\textbf{ワーカーが選択した求人群}と\textbf{その時に提示されていた候補求人群}を用いる。
\begin{itemize}
\item \textbf{ワーカー情報}: ワーカーID（\texttt{workerId}）、氏名（\texttt{name}）、資格（\texttt{qualifications}）など。
\item \textbf{セッション情報}: 勤務日（\texttt{workDate}）、開始時刻（\texttt{startTime}）、職種名（\texttt{jobTitle}）、業務内容（\texttt{jobContent}）。
\item \textbf{求人情報}: 介護項目（\texttt{careItems}）、施設名（\texttt{facilityName}）、給与（\texttt{salary}）、交通費（\texttt{transportationAllowance}）など。
\item \textbf{求人候補集合}: その時点で提示された求人候補群（\texttt{availableJobs}）。
\end{itemize}

\subsubsection*{推薦アルゴリズム構成}
	\begin{itemize}
		\item \textbf{Sentence-BERT ベース}: 求人タイトル・業務内容・介護項目・施設・勤務条件など複数項目の重み付けで統合類似度を算出。
		\item \textbf{項目別の重み付け比較}: 求人を構成する複数項目（職種名、業務内容、介護項目、施設、勤務条件など）の重み配分パターンを比較し、最適構成を探索。
		\item \textbf{時間重み付け比較}: 履歴の新しさ（直近重視・長期安定など）を反映する時間重みパターンを比較し、嗜好のドリフトに頑健な設定を探索。
		\item \textbf{ベースライン}: 職種のみ／介護項目のみで推薦する軽量モデルを実装し、BERTとの差分を測定。
		\item \textbf{業務回避パターン}: 過去履歴から避けている業務を推定し、ペナルティを付与。ユーザースタディで得られた知見であるため、追加実験の章で詳述。
	\end{itemize}

\subsubsection*{スコア統合の考え方}
BERTスコアは職種や業務内容の\textbf{意味的距離}を評価し、条件差分や履歴平均との統合により総合スコアを構成する。利用頻度に応じて重みを動的に調整し、ライトユーザーとヘビーユーザーで推薦方針を切り替える設計としている。

\subsubsection*{評価設計}
	\begin{itemize}
		\item \textbf{Top-K精度}: Top-1/3/5 を基本指標とし、実務的推薦の再現性を評価。
		\item \textbf{複合スコア}: Top-1/3/5 を1つの値に集約するため、各Top-K精度（0〜1）を用いて
	\[
	S_{\text{composite}} = 0.5\,\text{Top-1} + 0.3\,\text{Top-3} + 0.2\,\text{Top-5}
	\]
		と定義する（例：Top-1=39.0\%は0.390として扱う）。マッチングアプリ内では最高スコアのものを1つだけ提示する想定であるため、Top-1を重視しつつTop-3/5も考慮する形とした。
		\item \textbf{分割方法}: 段階的学習評価では、履歴の最初の\textbf{10件を固定テストデータ}として、その後に続く履歴データを学習データとして$k$件用意し、精度を算出する（$k$を変化させて学習曲線を得る）。
		\item \textbf{学習曲線評価}: 学習件数を段階的に増やして性能変化を分析。
	\end{itemize}

\section{予備実験1：日本語BERTモデルによる単語間類似度測定}
自然言語処理モデルの代表例としてBERTがある。本研究では日本語に特化したcl-tohokuモデルを利用し、単語間のコサイン類似度を計測した。しかし、「介護」と「極悪非道」の類似度が0.678であったり、「看護師」と「ナース」よりも「介護士」と「ナース」のほうが数値的に近かったりと、直感とずれる結果が得られた。この結果から、単一モデルに依存せず、横断的に複数モデルを検討する重要性が示された。
\section{予備実験2：BERTモデルの横断評価}
予備実験1の結果を受け、単語レベルではなく\textbf{職種表現全体の意味}を捉えやすい埋め込み表現を前提に、複数のBERT系モデルを横断的に比較した。評価指標として、アンカー職種に対して「類似職種の平均スコア」と「非類似職種の平均スコア」の差を取り、\textbf{分離度}として定義する。分離度が大きいほど、類似/非類似をより明確に区別できる。

	比較対象は、BERT系の\textbf{CLS}埋め込みと平均プーリング、ならびにSentence-BERTの日本語・多言語モデルである。いずれもコサイン類似度を用い、各アンカーの分離度を算出した後、アンカー平均をモデルの総合指標とした。

	\subsubsection*{CLS・平均プーリング・Sentence系の違い}
	BERT系モデルは入力文をトークン列として処理し、各トークンに対応する埋め込みを出力するため、「文全体」を1本のベクトルにまとめる\textbf{プーリング}が必要になる。
	\begin{itemize}
		\item \textbf{CLS埋め込み}: 文頭に付与される\texttt{[CLS]}トークンの最終層ベクトルを文表現として用いる。分類タスク向けに設計された表現であり、短文や語順の揺れに対して文意が不安定になる場合がある。
		\item \textbf{平均プーリング（mean pooling）}: 最終層のトークン埋め込み（\texttt{[PAD]}を除く）を平均し、文表現とする。文中の情報を広く集約できるため、短文の意味が安定しやすい。
	\end{itemize}
	一方、\textbf{Sentence-BERT（Sentence系）}は、Sentence-BERTのように\textbf{文同士の類似度}が直接高くなるよう学習（対照学習・ペア学習など）されたモデルであり、コサイン類似度での近さが「文意の近さ」に対応しやすい。

\section{本実験2：複数項目の重み付けによる精度向上}
本実験1では、複数項目を統合しても\textbf{均等重み}だけでは精度が頭打ちになり、さらに学習件数を増やすと精度が低下する傾向が見られた。そこで本実験2では、均等重み（本実験1）を基準として、求人タイトル、業務内容、介護項目、施設、勤務時間、時給、勤務日など7項目の\textbf{どの項目を相対的に重視するか}を変化させ、精度への影響を評価する。

\section{本実験3：時間重み付け比較}
本実験1・2では、重み付けにより精度差は生じるものの、学習件数が増えると精度が低下する傾向が共通して観察された。これは、古い履歴が現在の嗜好から外れていく影響が無視できないことを示唆する。そこで本実験3では、\textbf{履歴の新しさを評価に反映する}時間重み付けを導入し、この傾向を緩和できるかを検証する。

具体的には、過去履歴の寄与に対して、直近ほど大きな重みを与える減衰関数（指数・線形・ウィンドウ・セッション順など）を比較する。特徴量配分は6種（表\ref{tab:exp4-feature-patterns}）に固定し、各特徴量配分に対して時間重みを組み合わせて評価した。以降の上位パターン表は、\textbf{学習ステップ20（履歴20件）}の評価結果を主に用い、学習ステップ別の推移は表\ref{tab:time-weighting-steps}に示す。

主要な時間重み付けの代表例は付録\ref{app:weight-patterns}に移し、本文では考え方のみを簡単に整理する。
\begin{itemize}
	\item \textbf{時間減衰なし：}全履歴を同一の重みで参照する基準。
	\item \textbf{指数減衰：}履歴が新しいほど重く、古いほど急速に軽くする。最近の応募・閲覧に強く引っ張られるため、嗜好が短期間で変わるユーザーに対して追従しやすい。一方で、過去の安定した好みを反映しにくくなる場合がある。
	\item \textbf{線形減衰：}履歴の新しさに応じて重みを一定の割合で段階的に小さくする。指数減衰よりも「古い履歴もある程度は残す」形になりやすく、短期と長期のバランスを取りたい場合に適する。
	\item \textbf{期間制限型：}一定期間内の履歴だけを参照し、それ以前は参照しない。古い履歴の混入を確実に防げるため、嗜好の変化や季節要因の影響を受けやすい場合に有効である。
	\item \textbf{セッション順の減衰：}日付ではなく行動の順序で「新しさ」を定義し、直近ほど重くする。タイムスタンプの精度が十分でない場合でも、相対的な新旧を用いて最近の行動を優先できる。
\end{itemize}

\section{本実験4：時間重み自動選択の実装と結果}
本実験3の結果から「短期志向が優位だが個別差が大きい」ことに気づいたため、履歴のドリフト傾向に応じて短期/長期の減衰関数を自動選択する\textbf{時間重み自動判別}を実装した。本研究で用いたデータは履歴に日付情報が含まれるため、日付ベースの候補（直近重視の指数減衰、期間制限型）からワーカーごとに切り替える。

自動選択の中核は「履歴のドリフト」検出である。過去履歴の埋め込みベクトルを作成し、直近ウィンドウ（最小2件・最大5件、履歴長の1/3を上限）とそれ以前の履歴を分け、各集合の平均ベクトル間のコサイン類似度を計算する。ここで \textbf{drift = 1 - similarity} と定義し、値が大きいほど最近の行動が過去と異なる（志向性が変化している）と解釈する。ドリフトが小さい場合（閾値0.12未満）は安定とみなし、長期履歴を厚めに使う期間制限型へ切り替える（直近90日以内の履歴を同一重みで参照し、それ以前の履歴を参照しないことで「最近に寄せすぎない」参照範囲を与える）。ドリフトが大きい場合は短期変化の追従を優先し、直近重視の指数減衰を維持する。判定結果（採用した方式、ドリフト値、最近ウィンドウ長）はワーカー単位にキャッシュし、同一履歴長での再計算を省略する。

時間重み自動判別の検証は20名データ（読み込み成功18名）で実施し、特徴量配分を均等（\texttt{equal}）に固定したうえで、時間重みのみを比較した。その結果、時間重み自動判別は\textbf{時間減衰なし}を上回り、\textbf{直近期間の線形減衰}が最も高い平均Top-5を示した。自動判別は短期の行動変化への追従性を高める一方、ドリフト推定は履歴量や埋め込みのばらつきに影響されるため、固定的な減衰との併用・比較が有効である。
